# 发布与更新（GitHub Releases）

仓库已公开：`https://github.com/tysb121/english-app`。应用通过 **GitHub Releases API**（无需 token）检查更新并下载 APK，不依赖自建服务器。

## 版本约定

| 位置 | 格式 | 说明 |
|------|------|------|
| `pubspec.yaml` | `version: X.Y.Z+N` | `X.Y.Z` 为 versionName；`N` 为 Android versionCode |
| GitHub Release tag | `vX.Y.Z` | **必须**与 pubspec 的 version **name**（`X.Y.Z`）一致 |
| APK 资源名（建议） | `english-app-vX.Y.Z.apk` | 应用会取 Release 里第一个 `.apk` 资源 |

应用用 `package_info_plus` 读本地 `version`（不含 `+N`），与远端 `tag_name`（可带或不带前导 `v`）做 semver 风格比较。远端更大才提示更新。

发版前先改 `pubspec.yaml` 的 `version`，再打同号 tag。

## 密钥与签名（仅本机）

**切勿**把 keystore、`key.properties` 或密码提交到 Git。`.gitignore` 已忽略 `*.jks`、`*.keystore`、`key.properties`。

### 1. 生成本地 keystore（只需一次）

在本机（推荐 Windows，Flutter 在 `D:\flutter`）执行：

```bash
keytool -genkey -v -keystore upload-keystore.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

把 `upload-keystore.jks` 放到安全目录（例如 `android/` 之外、或本机密码管理器旁）。

### 2. 写 `android/key.properties`（不提交）

```properties
storePassword=你的store密码
keyPassword=你的key密码
keyAlias=upload
storeFile=../upload-keystore.jks
```

`storeFile` 相对 `android/app/` 解析；按你实际路径改。

### 3. 构建行为

`android/app/build.gradle.kts` 在存在 `android/key.properties` 时用正式签名；**不存在时** release 仍用 debug 签名，方便本机试跑，但 **不要**把 debug 签名包当作长期公开发布包。

## 发版步骤

1.  bump `pubspec.yaml`：例如 `1.0.0+1` → `1.0.1+2`（name +1，build 也建议 +1）。
2. 构建：

   ```bash
   flutter build apk --release
   ```

   产物默认：`build/app/outputs/flutter-apk/app-release.apk`。可复制改名为 `english-app-v1.0.1.apk`。
3. 创建 GitHub Release：

   ```bash
   gh release create v1.0.1 \
     build/app/outputs/flutter-apk/app-release.apk#english-app-v1.0.1.apk \
     --title "v1.0.1" \
     --notes "本版改动说明……"
   ```

   或用网页：Releases → Draft a new release → tag `v1.0.1` → 上传 APK。

4. 手机打开「我的」→「检查更新」，应提示新版本并可下载安装。需允许「安装未知应用」。

也可运行仓库脚本（见下）自动读版本、尝试构建并打印 / 执行 `gh release create`。

## 辅助脚本

```bash
bash tool/release_apk.sh           # 读版本、构建（若有 flutter）、打印 gh 命令
bash tool/release_apk.sh --publish # 若已 gh auth，则创建 Release 并上传 APK
bash tool/release_apk.sh --skip-build  # 只打印命令（APK 需已存在）
```

无 Android SDK / 构建失败时脚本仍会打印命令，不阻断文档与代码合入。

## 应用内更新行为

- 「我的」→「检查更新」：立即请求 `GET https://api.github.com/repos/tysb121/english-app/releases/latest`（未鉴权）。
- 启动后在「首页壳」上 **软检查**：最多每天一次，有新版本才弹窗；失败静默。
- 下载到临时目录后用系统安装器打开（`open_filex`）。清单已声明 `REQUEST_INSTALL_PACKAGES`。
- **不**在应用内存放 GitHub token；API Key 仍只走安全存储。

## 首次 APK

若当前环境未生成正式 keystore，或第一次在 Windows 上打包：按上文生成 keystore → 配置 `key.properties` → `flutter build apk --release` → `gh release create`。Linux CI / 无 SDK 的机器可只合入代码与文档，首包在装有 Flutter + Android SDK 的机器上打。
