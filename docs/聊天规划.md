## 这一刀做完是什么样

同一条线程里走完这个循环：

1. 用户发出一条。气泡立刻留在屏幕上，并写入本地。
2. 程序把全文投影成模型该看到的历史。没超过预算就原文发送。
3. 超过预算时，先做一次不带工具的摘要，再把检查点加最近几轮发给模型。
4. 模型的纯文本回复追加到同一条线程。
5. 失败时用户那条还在，下面是原因和「重试」。重试不再追加一条用户消息。
6. 关掉再打开，线程还在。没有回复的那条不自动重发。

屏幕上始终是全文。检查点不画成用户气泡。有一份非空检查点时，线程里用一行小字写「更早的对话已收成检查点」。

这一刀包含：

- 一条教练线程和底部输入
- 上下文投影和检查点
- 纯文本的回复请求、纯文本的摘要请求
- 失败后的一次自动重试，以及用户点的「重试」
- 线程和检查点跟课程进度存在同一个文件里，并仍能读旧的课程文件
- 从现在的「今天」页进入这条线程

这一刀不包含：

- 难度三选一，以及按难度换词带
- 把认词、场景、角色扮演、四题考核、错词、笔记、打卡接进这条线程
- 把模型回复交给课程引擎的 `applyModelResponse`
- 改复习日期或宣布打卡
- 流式、思考、工具、图像
- 调用 TokenHub
- 拆掉认词、考核、错词的现有入口
- 安装到手机

密钥门仍是现在的设置门。没有 DeepSeek 密钥不能发。开场白由本地写上一句，不为开场调用模型：「直接发一句想练的英文，或用中文告诉我你想说什么。」

教练这一轮的系统说明放在检查点外面，不进线程：

> 你是「今日英语」里的英语教练。用简短中文带用户练英文，一次只推进一小步。用户要练的句子用英文。不宣布打卡，不安排复习日期，不声称进度已经记下。

这只是闭环用的身份。关卡接进来之后，系统说明再改成按当天计划说话，仍不放进检查点。

## 程序和模型

这一刀的分工：

| 程序 | 模型 |
|---|---|
| 线程全文、消息 id、检查点存哪 | 根据投影回复一条教练话 |
| 何时折叠、切在哪一条、保留哪四轮 | 把更早的对话收成检查点正文 |
| 摘要没变短就记住这次切分 | |
| 失败、重试、错误文案不写回模型历史 | |

以后关卡接进来时，程序继续拥有：难度词带、当天冻住的计划、离线认词比对、第 2/4/8 天、错词间隔、关卡顺序、续练位置、同一次出现只判一次、打卡、笔记的保存或跳过、发给模型的内容。模型继续拥有 `fill_scene`、`grade_open`、`explain`。那三件仍是 JSON。聊天回复和上下文摘要是纯文本，不用 `response_format: json_object`。

现有的 `deepSeekChat` 强制 JSON，不能拿来发这条线程。另建一个纯文本构造。探测请求保持原样，不进入这条线程。

## 压缩

常量与工作室相同。测试可以注入更小的预算。

- 投影字符数超过 12000，并且用户消息多于 4 条，才折叠。
- 保留最近 4 条用户消息，以及从那一条起往后的全部消息，逐字保留。
- 只计用户和助手。去掉空白后为空的正文不进投影。这一刀没有工具消息。
- 长度按正文字符数相加，不按 token。

切点是倒数第 4 条用户消息。`untilMessageId` 是这条消息的 id。

已保存的检查点按这个表处理：

| 情况 | 发给模型的历史 | 还要不要摘要 |
|---|---|---|
| `untilMessageId` 相同，正文非空 | 检查点加保留的尾巴 | 不要 |
| `untilMessageId` 相同，正文为空 | 全文 | 不要。空正文表示这次切分没有变短 |
| 没有对上的检查点 | 全文留作失败回退，同时给出待摘要的源和尾巴 | 要 |

检查点作为一条 `user` 消息发给模型：

```text
以下是更早对话的检查点。把它当作已成立的背景，从后面的消息继续，不要复述这段检查点。

<compacted-summary>
……
</compacted-summary>
```

摘要源的接法：上一份非空检查点的 `untilMessageId` 若仍在新切点之前，源的开头写「已有检查点：」加上那份正文，然后只接那条消息到新切点之间的内容。否则从线程开头摘到切点。每条写成「用户：」或「助手：」。源去掉空白后为空，则不摘要，直接发全文。

摘要请求：

- 另一次补全，不带工具，不是 JSON 模式。
- system 用下面的检查点说明，user 是摘要源。
- `stream: false`，`thinking.type` 为 `disabled`，`reasoning_effort` 为 `none`，`temperature` 为 0。
- `max_tokens` 为 800。`finish_reason` 不是 `stop` 时，这次摘要作废。
- 不写课程进度。

检查点说明，空节写「无」：

```text
你在为英语教练整理更早的对话。只输出检查点正文，用简体中文，按下面的小节顺序，空节写「无」。

## 正在练什么
## 已经练过的词和句子
## 停在哪里
## 还没做完的事
## 需要记住的约束

合并已有检查点里仍然成立的事实，丢掉过时的。不要调用工具，不要写小节以外的话。
```

工作室用的是网站任务的五个小标题。这里换成练习用的五节，折叠办法不变。

摘要结果：

- 正文去掉空白后非空，并且短于摘要源：存下正文。回复请求用检查点加尾巴。
- 正文为空，或没有更短：存下 `{ "untilMessageId", "text": "" }`。回复请求用全文。同一切分不再摘要。
- 网络失败、非 200，或 `finish_reason` 不是 `stop`：不写入检查点。回复请求用全文。下次仍可对同一切分再摘要。
- 请求中断：不写回复，也不写检查点。

回复请求：

- system 是教练身份，后面是投影后的消息。
- 纯文本，`temperature` 为 0.4，`max_tokens` 为 800。
- 同样关闭思考、不流式、不带工具、不用 JSON 模式。
- `user_id` 用本机 `installId`。
- 地址只接受 `https`。
- 状态文案沿用能力设计：401 密钥无效，402 余额不足，400/422 地址或模型名不被接受，429 稍后再试，其余为服务暂时不可用。
- HTTP 200 但正文取不出、500、503、状态 0：自动再请求一次。401、402、400、422、429 不自动重试。
- 自动一次之后仍失败，留给用户点「重试」。
- `finish_reason` 不是 `stop` 时，不把截断正文当成一条成功回复。
- 用现有解析取出 `choices[0].message.content`。不进入课程 JSON 的写入。

一次只进行一个模型请求。摘要和回复串行。正在请求时不再接受新的发送。

## 保存

进度文件现在就是 `LessonStore.toJson()`。`restore` 只读它认识的字段，下一次 `progressJson()` 会丢掉它不认识的字段。聊天不能塞进 `toJson()`。

保存改成外壳，读取兼容旧文件：

```json
{
  "kind": "english-app",
  "lesson": {},
  "chat": {
    "messages": [{ "id": "m1", "role": "user", "content": "..." }],
    "contextSummary": { "untilMessageId": "m3", "text": "..." }
  }
}
```

- 读到 `lesson` 对象：课程用它还原，聊天用 `chat`。
- 读到旧文件：整份仍交给 `LessonStore.restore`，聊天为空。
- 之后每次保存都写外壳。课程引擎自己的 `progressJson()` 仍只表示课程，外壳包在它外面。
- 消息 id 一旦写入就不变，检查点靠它定位。
- `role` 只有 `user` 和 `assistant`。
- 密钥不进这个文件，不进日志。
- 检查点存在 `contextSummary`，不再复制成一条可见消息。
- 整段提示词不另写进模型调用日志。线程本身就是要留下的记录。

失败文案留在内存。重启后若最后一条是用户消息且没有助手回复，显示「重试」，不自动发送。

## 测试

不访问网络，用现有的假 Poster。

投影：

- 未超过 12000 字，或用户消息不超过 4 条：不折叠，历史等于全文。
- 超过预算且用户消息多于 4 条：尾巴从被保留的那条用户消息开始。此时失败回退仍是全文。
- 检查点 id 对上且正文非空：历史是检查点加尾巴，不再给出待摘要。
- 检查点 id 对上且正文为空：历史是全文，不再给出待摘要。
- 上一份检查点落在新切点之前：摘要源包含「已有检查点」以及中间消息。

发送：

- 摘要更短：存下正文。回复请求里有检查点包装，没有被折掉的更早原文。
- 摘要没变短：存空正文。回复请求是全文。
- 摘要请求失败：不存检查点。回复请求仍发出，用的是全文。
- 回复失败：用户消息只有一条。重试不再增加用户消息。
- 回复成功不改变课程日期、打卡和错词。
- 旧进度文件仍能还原课程。
- 保存后再读，线程和检查点都在。
- 空白不发出请求。

## 再下一刀

闭环的测试通过之后，再按 `prototype/index.html` 把主路径换成一条线程，并回写界面.md。

1. 第一次打开三选一：新手、简单工作对话、更长的表达。各带一句例子。这一屏不问密钥。
2. 然后是 DeepSeek 密钥。测试连接仍用现在的文案。
3. 认词在线程里一次列出当天全部中文。本地比对，忽略大小写和首尾空格。
4. 通过后再要场景。场景仍是一次 `fill_scene`。然后逐句接话，再一题一题考核。笔记的保存和跳过留在同一条线程。跳过仍然算打卡。
5. 词表只做查阅。关掉再打开停在同一句。

难度要改选词，不只改提示词。新手不从种子词表开头的 standup、bandwidth 开始，先用已经写在种子里的短句：sounds good、let me check、running late、I'll get back to you、keep me posted、due today、as soon as possible、out of office、lunch break、wrap up、quick question。简单工作对话用会议用语。更长的表达用 take this offline、stakeholder、alignment 这一档。每天仍是 5 个。选择存在本地，并决定教练句子有多短、中文有多少。当天计划已经冻住之后再改难度，从下一天生效。密钥仍在第一次模型调用之前要有。

这些词带和关卡留到下一刀。
